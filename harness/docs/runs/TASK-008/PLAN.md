# TASK-008 · PLAN — frontend 템플릿 보완

작성일: 2026-09-07
대상: `harness/templates/frontend` (React + Vite)
참조: `projects/model_test/src/frontend`
상태: 사용자 요청으로 즉시 실행

> 하니스에는 작업 기록 규약이 없어 `projects/*/docs/runs`와 같은 구조를 `harness/docs/runs`에 만들어 사용한다.

## 배경

`projects/model_test`에서 실사용하며 다듬은 화면 규칙이 템플릿에는 아직 없다. 템플릿을 쓰는 다음 프로젝트가 같은 시행착오를 반복하지 않도록 검증된 패턴만 역으로 옮긴다.

## 범위

| # | 항목 | 근거 |
| --- | --- | --- |
| R1 | 상단 우측을 **로그인 ID 배지**로 | 지금은 이름·역할만 작게 표시된다 |
| R2 | 명령 버튼 **가로 폭 통일** | 결과 화면 버튼 3개의 폭이 제각각이다 |
| R3 | 상단 탭을 **모서리만 둥근 사각형 + 동일 폭** | 알약/사각 혼재 방지 |
| R4 | 좌측 상자 **접기/펼치기** | 파라미터가 늘어나면 사이드바가 길어진다 |
| R5 | **얇은 슬라이더·스크롤바** | 기본 스타일이 두껍고 화면 밀도와 어긋난다 |
| R6 | **사이드바/본문 독립 스크롤** | 창 스크롤이 좌측 메뉴까지 끌고 간다 |
| R7 | 결과 **크롬 스타일 탭 + 닫기(×)** | 여러 결과를 오가며 보기 |
| R8 | **X는 숨김, 우클릭은 삭제** | 실수로 지우는 것을 막는다 |
| R9 | 답변 **저장 버튼**(누를 때만 저장) | 자동 저장은 잡음을 만든다 |
| R10 | 입력이 바뀌면 **답변 비우기** | 이전 답이 새 질문의 결과처럼 보인다 |
| R11 | 모델명에 **LLM/VLM 표기 + 유형 필터** | 이미지 입력 가능 여부를 한눈에 |
| R12 | 답변 비교에 **모범답변·심판 모델·순위표** | 비교 화면의 실제 쓸모 |

제외: 인증·권한 구조 변경(템플릿의 `features/auth`, `admin`은 그대로 둔다), 실제 백엔드 연동, 스트리밍(템플릿 서비스는 목업 유지).

## 설계

- 새 컴포넌트는 템플릿의 기존 경계를 따른다 — 재사용 UI는 `components/`, 업무 화면은 `features/workbench/`.
- 목업 데이터(`data/sample.js`)에 모델 목록(유형 포함), 저장된 실행, 심판 후보를 추가해 템플릿만으로도 화면이 동작하게 한다.
- `services/modelService.js`에 `saveRun`, `compareRuns` 목업을 추가한다. 실제 API로 교체할 지점을 주석으로 남긴다.
- CSS는 기존 파일 뒤에 읽기 쉬운 블록으로 덧붙이고, 바꿔야 하는 규칙(`.tab`, `.workspace`, `.sidebar`, `.content`, range)은 뒤에서 덮어쓴다.
- 순위 계산은 점수 기준으로 화면에서 수행한다(모델이 매긴 순서를 신뢰하지 않는다).
