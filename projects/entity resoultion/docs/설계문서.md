# LCI 물질명 매칭 지식 그래프 설계문서

## 1. 데이터 흐름

```text
src/data/knowledge-graph             관리 원본
        │ npm run data:publish
        ▼
public/data/knowledge-graph          브라우저 조회용 생성본
        │ fetch(manifest.json)
        ▼
React 화면 ── 항목 상세 / 그래프 조회 / LCI 매칭결과 테스트
```

`public`은 런타임 조회 전용이다. JSON의 구조 변경과 내용 수정은 `src/data/knowledge-graph`에서 수행한다.

## 2. 폴더 설계

```text
src/
├─ data/knowledge-graph/             관리 원본
│  ├─ manifest.json
│  ├─ nodes/{structure,materials,terminology,other}.json
│  ├─ edges/{structure,materials,terminology,reference-mappings}.json
│  └─ versions/baseline.json
├─ utils/loadGraphData.js             매니페스트 기반 로더
└─ components/                        그래프, 상세, 매칭 UI

scripts/
├─ publish-graph-data.mjs             원본 → public 생성본 복사
└─ split-graph-data.mjs               기존 단일 JSON 최초 분할용
```

## 3. JSON 설계

### 항목

```json
{
  "node_id": "CON:pc",
  "node_type": "concept",
  "name": "폴리카보네이트",
  "revision": 1,
  "updated_at": "2026-09-14T00:00:00.000Z",
  "props": {}
}
```

### 관계

```json
{
  "edge_id": "E:PC:REF",
  "edge_type": "BRIDGES_TO",
  "from": "CON:pc",
  "to": "REF:pc_granulate",
  "cardinality": "m:n",
  "revision": 1,
  "updated_at": "2026-09-14T00:00:00.000Z",
  "props": { "lci_db_name": "polycarbonate production", "ref_id": "6829" }
}
```

### 프록시 매핑

프록시는 `BRIDGES_TO` 관계의 속성으로 표현한다. 원 물질과 동일하지 않음을 `same_substance: false`로 고정하고, 선정 근거와 불확실성 검토를 기록한다.

```json
{
  "match_type": "프록시",
  "mapping_kind": "lci_proxy",
  "same_substance": false,
  "proxy_reason": "직접 LCI 데이터 부재",
  "conservatism_direction": "과소평가 가능",
  "uncertainty_comment": "수지계 차이 확인 필요",
  "proxy_review_required": true
}
```

## 4. 버전관리 설계

현재 정적 화면은 브라우저별 수정 이력을 `localStorage`에 기록한다. 공유 환경에서는 아래의 낙관적 잠금 방식을 적용한다.

1. 수정 요청에 대상 ID와 현재 `revision`을 포함한다.
2. 서버는 저장된 revision과 일치할 때만 변경한다.
3. 성공 시 revision을 1 증가시키고, 이전값/이후값/수정자/수정시각을 변경 이력에 추가한다.
4. 승인된 변경만 원본 JSON과 `data_version`에 반영한다.

## 5. 운영 절차

1. `src/data/knowledge-graph`에서 JSON 수정
2. JSON 문법 및 항목·관계 ID 참조 검증
3. `npm run data:publish` 실행
4. `npm run build` 실행
5. 생성본과 화면에서 변경사항 확인
