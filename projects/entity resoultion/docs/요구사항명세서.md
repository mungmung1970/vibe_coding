# LCI 물질명 매칭 지식 그래프 요구사항 명세서

## 1. 목적

제품유형, 파트, 구성품, 물질개념, 참조물질을 연결해 LCI DB의 `ref_id`를 탐색·검토·수정할 수 있는 지식 그래프를 제공한다.

## 2. 데이터 관리 요구사항

| ID | 요구사항 | 수용 기준 |
| --- | --- | --- |
| DR-01 | 데이터 원본은 `src/data/knowledge-graph`에서 관리한다. | 원본 JSON은 항목·관계 유형별 파일로 존재한다. |
| DR-02 | 화면은 `public/data/knowledge-graph`의 생성본을 조회한다. | `manifest.json`으로 모든 항목·관계 파일을 읽는다. |
| DR-03 | 단일 파일명에 특정 제품·파트명을 넣지 않는다. | `structure.json`, `materials.json` 등 역할 기반의 고정 파일명을 사용한다. |
| DR-04 | 항목과 관계는 개정번호와 수정시각을 가진다. | 모든 JSON 항목에 `revision`, `updated_at`이 존재한다. |
| DR-05 | 수정 이력은 대상 항목/관계 ID별로 조회할 수 있다. | UI의 수정 이력에서 작업, 시각, 개정순서를 확인한다. |
| DR-06 | LCI 참조 매핑에는 DB명과 `ref_id`를 보관한다. | `BRIDGES_TO` 관계와 참조물질 속성에 값이 존재한다. |
| DR-07 | 동일 물질의 대체어와 프록시 매핑을 구분한다. | 대체어는 동일성 유지, 프록시는 `same_substance: false`를 가진다. |

## 3. 기능 요구사항

| ID | 요구사항 | 수용 기준 |
| --- | --- | --- |
| FR-01 | 사용자는 제품유형·파트·구성품·도메인·물질·참조물질 조건으로 그래프를 조회한다. | 선택된 조건과 연결된 상·하위 항목이 표시된다. |
| FR-02 | 사용자는 항목 또는 관계를 선택해 상세 정보를 조회한다. | 항목 속성, 참조물질명, 상세정보, 상위 관계, 하위 관계 순으로 표시된다. |
| FR-03 | 사용자는 수정 모드에서 항목·관계를 추가, 수정, 삭제한다. | 변경 후 해당 대상의 수정 이력이 남는다. |
| FR-04 | 신규 생성 시 동일 제품유형·파트를 감지한다. | 순번 신규 생성, 기존 항목 수정, 기존 파트 교체, 취소를 제공한다. |
| FR-05 | 매칭결과 테스트는 입력 물질명에 대해 LCI DB명과 `ref_id` 후보를 보여준다. | 프록시 매핑이면 선정 근거와 불확실성을 함께 표시한다. |

## 4. 비기능 요구사항

- 그래프 캔버스는 `label`, `surface_form` 등을 숨겨 과밀을 줄이되, 상세 화면에서는 모든 연결 항목을 표시한다.
- 데이터 수정 후 `npm run data:publish`로 생성본을 갱신한다.
- 다중 사용자 동시 편집, 승인, 서버 단위 되돌리기는 API와 DB 도입 시 구현한다.
