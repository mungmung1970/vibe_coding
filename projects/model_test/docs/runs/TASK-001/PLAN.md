# TASK-001 · PLAN — 모델 테스트 콘솔 구축

## 1. 요구

참조 이미지 두 장을 기준으로, 로컬 모델을 골라 서빙하고 파라미터를 바꿔가며 프롬프트 응답을 비교하는 콘솔을 만든다. backend와 frontend를 분리한다.

## 2. 범위

- 모델 등록부 스캔과 목록 제공
- 모델 선택 시 기존 서빙 중단 후 해당 모델만 vLLM으로 서빙
- 모델에 전달 가능한 모든 파라미터를 JSON으로 관리하고, 서빙된 모델에 맞춰 좌측에 노출
- 중앙 입력 → 우측 결과 스트리밍 표시
- 실행 기록 조회와 답변/파라미터 비교

제외: 인증, 다중 모델 동시 서빙, 외부 API 모델, 자동 채점

## 3. 설계 결정

| 결정 | 이유 |
| --- | --- |
| 백엔드를 파이썬 표준 라이브러리로 구현 | 프론트 템플릿의 무의존성 기조와 일치. 이 컨테이너에 FastAPI가 없고 설치가 환경에 영향을 줄 수 있다 |
| 파라미터를 JSON 카탈로그로 분리하고 `target`으로 전달 위치 지정 | 항목 추가가 화면·요청에 동시에 반영되고, 검증을 한 곳에서 한다 |
| 서빙을 상태 기계(`idle/starting/ready/stopping/error`)로 모델링 | "한 번에 한 모델" 불변식을 한 곳에서 강제한다 |
| 엔진을 인터페이스로 두고 프로세스 관리와 추론 호출을 분리 | vLLM 프로세스 수명과 요청 처리를 독립적으로 테스트한다 |
| 프론트는 하니스 템플릿 구조(components/data/state/services/styles/utils) 유지 | FRONTEND_STANDARD 준수 |

## 4. 인수 조건

AC1 모델 목록과 제공자/모델 선택이 동작한다
AC2 모델 전환 시 이전 서빙이 중단되고 새 모델만 서빙된다
AC3 서빙 완료 후 해당 모델에 맞는 파라미터가 좌측에 표시된다
AC4 프롬프트 실행 결과가 우측에 스트리밍으로 표시된다
AC5 실행 기록 조회·비교가 동작한다
AC6 백엔드/프론트 테스트가 모두 통과한다
