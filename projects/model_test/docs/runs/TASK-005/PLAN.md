## 2. 비밀정보 취급 (선결)

API 키는 **저장소 안에 두지 않는다.**

- 실제 키: `var/secrets.env` (저장소 밖 취급, 권한 600). `KEY=VALUE` 한 줄씩.
- 등록부 JSON에는 **환경변수 이름만** 적는다: `"api_key_env": "OPENAI_API_KEY"`.
- 서버는 기동 시 `MODEL_TEST_SECRETS_FILE`(기본 `var/secrets.env`)을 읽어 환경변수로 올린다.
- 로그·오류 메시지·API 응답에 키가 노출되지 않도록 마스킹한다.
- 대화에 노출된 기존 키는 폐기·재발급을 권고한다.

## 3. 설계

### 3.1 공급자 추상화 (R10)

현재 `Engine`은 로컬 vLLM 프로세스 전용이다. 외부 API 모델은 **서빙이 필요 없다**(항상 준비 상태). 다음과 같이 나눈다.

```
Model.provider_type: "local" | "openai" | "anthropic"
  local  → 기존 VllmProcessEngine (프로세스 기동/중단)
  remote → RemoteApiEngine (기동 없음, 즉시 ready, HTTPS 호출)
```

`ServingManager.serve()`는 원격 모델이면 프로세스를 띄우지 않고 상태만 `ready`로 만든다. "한 번에 한 모델" 불변식은 유지하되, 원격 모델 선택 시 로컬 프로세스는 중단한다(GPU 반환).

원격 모델 정의도 `models/<id>/model.json`으로 통일한다:

```json
{ "id": "gpt-5.2", "provider": "OpenAI", "provider_type": "openai",
  "remote_model": "gpt-5.2", "api_key_env": "OPENAI_API_KEY",
  "modality": "LLM", "capabilities": ["chat"] }
```

Anthropic은 메시지 형식이 달라 `RemoteApiEngine`이 공급자별 변환(요청·스트리밍 이벤트)을 담당한다.

### 3.2 저장 버튼 (R1)

- `inference.py`가 자동으로 기록을 남기던 것을 중단한다.
- `POST /api/v1/runs`를 신설해 클라이언트가 완료된 실행을 명시적으로 저장한다.
- 답변 패널에 `저장` 버튼. 저장 성공 시 버튼 상태를 `저장됨`으로 바꾼다.

### 3.3 모델 유형과 이미지 입력 (R11, R12)

- `modality`(`LLM`/`VLM`)를 모델 메타데이터에 추가. 없으면 `config.json`의 `vision_config` 유무로 추론.
- 목록 표시는 `이름 (VLM)` 형식. 사이드바에 유형 필터(전체/LLM/VLM).
- VLM 선택 시 입력 패널에 이미지 첨부 UI 노출. 이미지는 data URI로 변환해 전송하고, 공급자별 형식(OpenAI `image_url`, Anthropic `source.base64`, vLLM은 OpenAI 형식)으로 변환한다.
- 요청 크기 상한(기본 8MB)과 확장자 검증을 둔다.

### 3.4 답변 비교 (R9)

`POST /api/v1/runs/compare`를 확장한다.

- 모범답변 없음 → 기존처럼 답변·파라미터 차이만 반환(로컬 계산).
- 모범답변 있음 + 심판 모델 선택 → 해당 모델에 채점을 요청해 순위·근거를 함께 반환.
- 심판 모델 목록은 등록부의 원격/로컬 모델에서 고른다.

### 3.5 화면 (R2~R8, R13, R14)

- 탭·버튼 스타일(R3, R7), 슬라이더 두께(R13), 스크롤바 두께(R14)는 CSS만 수정.
- 접기/펼치기(R4)는 섹션별 상태를 스토어에 두고 헤더 클릭으로 토글.
- 답변 비우기(R2)는 모델 변경·프롬프트 입력 시 `answer`를 초기화.
- 우클릭 삭제(R5)는 `contextmenu` 이벤트로 소형 메뉴 표시.
- 탭 보기(R6)는 선택된 실행 id 목록을 탭으로 렌더.
- X 숨김(R8)은 `hiddenRunIds`를 두고 화면에서만 제외(기록은 유지).
