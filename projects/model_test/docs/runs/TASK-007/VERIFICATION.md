## 구조 변경

| 항목 | 이전(바닐라) | 현재(React) |
| --- | --- | --- |
| 진입 | `src/main.js` 수동 렌더 | `src/main.jsx` + `App.jsx` |
| 상태 | 자체 store(`set`/`setQuiet`) | `WorkbenchContext`(모델·서빙·실행), `HistoryContext`(선택·탭·비교) |
| 화면 | `components/*.js` 문자열 템플릿 | `components/*.jsx` + `features/workbench/*.jsx` |
| 스트리밍 | 스로틀 + 직접 DOM 조작 | ref 누적 + 60ms 커밋 |
| 빌드 | 없음 | Vite (`dist/`), 백엔드가 자동 선택해 서빙 |

`services/api.js`, `utils/markdown.js`, `utils/format.js`, `styles/index.css`는 그대로 재사용했다. 마크다운은 이스케이프 후 문자열을 만들므로 `dangerouslySetInnerHTML`로 넣어도 주입이 발생하지 않으며, 해당 이스케이프 테스트를 유지했다.

## 백엔드 변경

`config.py`에 `_frontend_dir()`만 추가했다 — `src/frontend/dist/index.html`이 있으면 빌드 산출물을, 없으면 소스 디렉터리를 서빙한다. 그 외 백엔드는 손대지 않았다(파이썬 유지, 테스트 42건 그대로 통과).

## 남은 사항

- **화면 수정 후 `npm run build`가 필요하다.** 빌드하지 않으면 백엔드가 이전 산출물을 계속 서빙한다. README에 명시했다.
- 하니스 템플릿의 인증·권한(`features/auth`, `admin`)은 도입하지 않았다. 이 저장소 백엔드에 인증이 없어 화면만 붙이면 실제 통제가 되지 않기 때문이다. 상단 배지는 `anonymous` 고정이다.
- 스트리밍 중 리렌더 성능은 60ms 커밋으로 제한했지만, 매우 긴 답변에서의 마크다운 재파싱 비용은 측정하지 않았다.
