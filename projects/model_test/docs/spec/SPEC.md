# SPEC · LLM Lab 모델 테스트 콘솔

버전: 0.2
작성일: 2026-09-07
성격: **소급 작성**. TASK-001에서 구현된 동작을 기준으로 기술했으며, 이후 변경은 `docs/spec/features/`의 기능 명세가 우선한다.

## 1. 목적

사내 로컬 모델을 골라 서빙하고, 파라미터를 바꿔가며 같은 프롬프트의 응답 차이를 확인한다. 화면 구성은 참조 이미지 두 장(프롬프트 테스트 / 결과 조회)을 따른다.

## 2. 용어

| 용어 | 뜻 |
| --- | --- |
| 등록부 | `models/` 아래의 모델 메타데이터 모음. 가중치 자체는 외부 스토리지에 있다 |
| 서빙 | 선택한 모델 하나를 vLLM 프로세스로 띄워 요청을 받을 수 있는 상태 |
| 실행(run) | 프롬프트 1회 요청과 그 결과·파라미터·지표의 기록 |

## 3. 기능 요구사항

### F1. 모델 선택과 단일 서빙

- F1.1 등록부를 스캔해 제공자·모델 목록을 제공한다. 서버 재시작 없이 목록이 갱신된다.
- F1.2 모델을 선택해 서빙을 시작하면 **기존에 서빙 중이던 모델은 중단된다.** 어느 시점에도 서빙 중인 모델은 최대 하나다.
- F1.3 서빙 상태는 `idle → starting → ready`로 전이하며, 실패 시 `error`와 사유를 알린다. 프로세스가 죽으면 종료 코드를 포함해 보고한다.
- F1.4 서빙 준비 대기 한도(기본 1800초)를 넘기면 실패로 처리하고 프로세스를 정리한다.
- F1.5 엔진 로그의 최근 내역을 화면에서 조회할 수 있다.
- F1.6 vLLM을 찾을 수 없으면 대체 응답을 만들지 않고 기동을 거부한다.

### F2. 파라미터 카탈로그

- F2.1 모델에 전달 가능한 모든 파라미터는 단일 JSON 정의(`app/data/parameters.json`)에서 관리한다.
- F2.2 각 항목은 컨트롤 종류·타입·범위·기본값과 **요청의 전달 위치**(`body`/`extra_body`/`chat_template_kwargs`/`client`)를 갖는다.
- F2.3 모델이 지원하지 않는 파라미터는 화면에 나타나지 않는다(`requires_capability`).
- F2.4 모델별로 기본값·범위·노출 여부를 재정의할 수 있다(`parameter_overrides`).
- F2.5 서버는 들어온 값을 카탈로그 기준으로 검증한다. 범위 초과·형식 오류·미지원 키는 422로 거부한다.
- F2.6 파라미터 추가는 JSON 수정만으로 화면과 요청에 동시에 반영된다.

### F3. 프롬프트 실행

- F3.1 시스템 프롬프트와 질문을 입력해 실행한다. Enter 실행, Shift+Enter 줄바꿈.
- F3.2 응답은 기본적으로 스트리밍으로 표시하며, 사고 과정(reasoning)은 본문과 분리해 다룬다.
- F3.3 서빙 준비 전이거나 다른 모델을 지정하면 실행을 거부하고 사유를 알린다.
- F3.4 완료 시 소요 시간·글자 수·토큰 수를 표시한다.
- F3.5 답변은 마크다운으로 렌더링하되, 모델 출력은 항상 이스케이프해 마크업 주입을 막는다.

### F4. 결과 조회와 비교

- F4.1 완료된 실행을 저장하고 모델·검색어·기간으로 조회한다.
- F4.2 실행 결과를 카드 목록으로 보고 개별 삭제할 수 있다.
- F4.3 둘 이상을 선택해 답변과 **파라미터 차이**를 나란히 비교한다.
- F4.4 외부 심판 모델을 사용하는 자동 채점은 범위 밖이다.

## 4. 비기능 요구사항

| 항목 | 기준 |
| --- | --- |
| 의존성 | 콘솔 서버는 파이썬 표준 라이브러리만, 프론트는 빌드 없는 ES 모듈만 사용 |
| 오류 형식 | `{"error": {"code", "message", "details"}}`로 통일 |
| 종료 | SIGINT/SIGTERM에서 서빙 모델을 정리하고 정상 종료 |
| 접근 | 인증 없음. 신뢰 가능한 사내망 바인딩을 전제로 한다 |
| 화면 규약 | `harness/docs/FRONTEND_STANDARD.md`의 색·레이아웃·소스 경계를 따른다 |

## 5. 범위 밖

- 인증·권한, 다중 사용자 격리
- 여러 모델 동시 서빙, 다중 GPU 분산 서빙
- 외부 API 모델(OpenAI 등) 연동
- 자동 채점/순위화
