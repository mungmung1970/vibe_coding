# FEAT-002 · 사고 과정(thinking) 진행 가시화

상태: 초안 (승인 대기)
관련 작업: docs/runs/TASK-002
작성일: 2026-09-07

## 배경

추론 모델은 본문보다 사고 과정(reasoning)을 먼저 생성한다. 현재 화면은 사고 과정을 `show_thinking`이 켜져 있을 때만 표시하고, 기본값은 꺼짐이다. 그 결과 `enable_thinking`이 켜진 모델에서는 사고 토큰이 흐르는 동안 답변 영역에 "응답을 생성하는 중입니다…"만 남는다.

실측(Qwen3.8-27B, 실제 브라우저):

| 구간 | 측정값 |
| --- | --- |
| Enter → 첫 글자 표시 | 12,622ms |
| 같은 요청의 서버 처리(사고 끄기) | 2,089ms |
| 사고 토큰 수(사고 켜기) | 171 tokens |

즉 12초 동안 화면은 아무 변화가 없고, 사용자는 멈춘 것과 구별할 수 없다. 서버·엔진에는 문제가 없다.

## 요구사항

### R1. 사고 중 진행 표시

reasoning 델타를 받는 동안 답변 패널은 사고가 진행 중임을 표시한다. 표시에는 경과 시간과 누적 사고 글자 수를 포함한다.

### R2. 사고 내용 노출은 기존 설정을 따른다

- `show_thinking = false`(기본): 사고 **내용**은 노출하지 않고 R1의 진행 표시만 보여준다.
- `show_thinking = true`: 기존 thinking 블록에 사고 내용을 실시간으로 표시하며, 진행 표시도 함께 유지한다.

`show_thinking`의 기본값은 바꾸지 않는다. 사고 과정이 화면 상단을 채우는 것은 기본 동작으로 적절하지 않다.

### R3. 본문 전환

첫 본문 델타가 도착하면 진행 표시를 감추고 답변 렌더링으로 전환한다.

### R4. 완료 후 지표

응답 완료 시 하단 통계에 사고 토큰 수(`usage.completion_tokens_details.reasoning_tokens`)를 함께 표시한다. 값이 없으면 표시하지 않는다.

### R5. 비추론 모델 무영향

reasoning 이벤트가 없는 모델(예: `exaone-4.5-33b`)에서는 기존 안내 문구를 그대로 유지한다.

## 비요구사항

- 파라미터 기본값 변경(`enable_thinking`, `show_thinking` 포함)
- 백엔드·엔진·API 응답 형식 변경
- 결과 조회 화면 변경
