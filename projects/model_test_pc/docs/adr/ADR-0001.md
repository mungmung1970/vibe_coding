# ADR-0001 · 서빙 계층을 두지 않는다

상태: 채택됨 · 2026-09-07

## 맥락

`projects/model_test`는 vLLM으로 로컬 모델을 직접 서빙한다. 그 구조에는 프로세스 수명주기, 단일 서빙 불변식, 기동 대기(2~13분), GPU 점유, 격리된 파이썬 환경(`.venv-vllm`, 8GB)이 따라온다.

이 프로젝트가 쓸 모델은 셋 다 **이미 HTTP로 제공된다** — 사내 gpt-oss 엔드포인트, OpenAI, Anthropic. GPU가 없는 PC에서도 돌아야 한다.

## 결정

**모델 서빙을 전혀 하지 않는다.** 등록부에 적힌 엔드포인트를 호출할 뿐이다.

- `serving_manager.py`(상태 기계), `engines.py`(프로세스 관리), `/api/v1/serving*`, 화면의 서빙 시작·중단·로그를 모두 제거했다.
- 공급자 차이는 `services/providers.py`의 어댑터 둘(OpenAI 호환 / Anthropic)로 격리한다.
- 모델은 항상 사용 가능하므로 "선택 = 즉시 사용"이다.

## 근거

| 대안 | 기각 사유 |
| --- | --- |
| model_test를 그대로 쓰고 로컬 모델만 비활성화 | 서빙 코드·상태·화면이 남아 오해를 부른다. vLLM 미설치 시 기동이 거부된다 |
| 서빙 코드를 옵션으로 두고 플래그로 끄기 | 두 경로를 모두 유지해야 하고, 실제로는 한쪽만 쓰인다 |
| model_test를 수정 | 그쪽은 GPU 서버에서 실제로 쓰이고 있다. 별도 프로젝트가 안전하다 |

## 결과

**좋은 점**: 의존성이 파이썬 표준 라이브러리뿐이라 어느 PC에서나 즉시 실행된다. 기동 대기가 없다. GPU 자원과 무관하다. 백엔드 소스가 서빙판보다 작다.

**비용**: 로컬 가중치를 직접 올릴 수 없다. 엔드포인트가 죽으면 이 콘솔에서 할 수 있는 일이 없고, 오류를 정확히 전달하는 것이 전부다. 파라미터 지원 차이를 모델별 프로필·`unsupported_fields`로 관리해야 한다.
